# سامانه کروکی — نسخه ۸ دسکتاپ و داکری

این نسخه بر مبنای رابط کاربری ارسالی کاربر و فرم‌های نمونه تهیه شده است. اطلاعات توسط نقشه‌بردار وارد و در PostgreSQL ذخیره می‌شود. کارشناس مسئول آن را بررسی و تأیید می‌کند و سرویس مستقل شما داده‌ها و فایل‌ها را از API دریافت می‌کند.

## تغییرات نسخه ۸

- پنل دسکتاپ با منوی ثابت سمت راست، فضای کاری عریض، فرم‌های چندستونه و جدول‌های مناسب کامپیوتر بازنویسی شده است.
- زیرگروه «اطلاعات برداشت و موقعیت» در تب «اطلاعات کروکی»، شش جزء منطقه، حوزه، بلوک، قطعه اصلی، قطعه فرعی و واحد را در یک ردیف زیر عنوان «کد ممیزی» نمایش می‌دهد. کلیدهای API و دیتابیس همان شش کلید قبلی‌اند.
- پس از «تحلیل نمایشی و بازبینی»، برگه‌ای مشابه چیدمان نمونه سیاق با اطلاعات واقعی کاربر نمایش داده می‌شود. همان برگه در پنجره بررسی کارشناس نیز وجود دارد.
- ترسیم قطعه، در صورت وجود، از هندسه پرونده مبدأ است و برچسب منبع دارد. در نبود هندسه، شکل نمایشی با برچسب «شماتیک و بدون مقیاس» نمایش داده می‌شود. هیچ هندسه‌ای از DXF استخراج یا در فرم نوشته نمی‌شود.
- نقشه موقعیت از مختصات پرونده مبدأ است و نقشه زمینه به اینترنت نیاز دارد. در نبود اینترنت، هندسه و موقعیت پرونده حفظ می‌شوند. اگر مختصات پرونده موجود نباشد، کادر موقعیت این موضوع را نشان می‌دهد.
- در «فایل‌ها و بازدید»، روش نقشه‌برداری به انتخاب یکی از هفت گزینه در فهرست کشویی محدود شده است. ثبت‌های قدیمی قابل خواندن‌اند؛ هنگام ارسال مجدد باید یک روش از فهرست جدید انتخاب شود.
- شماره‌ها و تاریخ‌های اختصاصی سیاق، از جمله شماره موقت، همچنان توسط این اپ تولید نمی‌شوند.

## رفتار ثبت اطلاعات

- برای هر درخواست، یک کروکی ثبت می‌شود. اصلاح پس از عودت، همان ثبت را با `revision` جدید به‌روزرسانی می‌کند.
- فرم شامل اطلاعات کروکی، حدود با طول و عرض معبر، وضعیت زمین و ردیف‌های بهره‌برداری، تنظیمات برداشت، اطلاعات بازدید و عکس‌های محل است.
- بخش مستغلات در این نسخه اجرا نشده است.
- شماره و تاریخ کروکی و شماره و تاریخ موقت توسط سیاق اختصاص داده می‌شوند؛ در خروجی محلی `null` هستند.
- انتخاب یا جایگزینی DXF فقط فایل انتخاب‌شده را در حافظه رابط تغییر می‌دهد. هیچ درخواست ذخیره‌سازی به سرور، استخراج هندسه یا تغییر خودکار جدول اطلاعات انجام نمی‌شود.
- مرحله «تحلیل نمایشی» هیچ جدول، مقدار هندسی یا اطلاعات فرم را تغییر نمی‌دهد. مساحت، حدود و بهره‌برداری توسط کاربر وارد می‌شوند.
- ذخیره در دیتابیس و فایل‌های دائمی فقط با دکمه «ثبت اطلاعات و ارسال به کارشناس مسئول» انجام می‌شود. پیش‌نویس قبل از این دکمه در حافظه صفحه است و با Refresh از بین می‌رود.
- تأیید کارشناس به معنی «آماده انتقال» است. اپ هیچ ارتباط یا ارسال خودکاری به سیاق ندارد و شماره پیگیری سیاق تولید نمی‌کند.

## اجرای اولیه

Docker Desktop را اجرا کنید. در پوشه پروژه:

```bash
docker compose up -d --build
docker compose ps
```

نشانی سامانه: `http://localhost:3000`

در ویندوز می‌توانید از `START.bat` و `STOP.bat` استفاده کنید.

| نقش | نام کاربری | رمز عبور | کد ورود محلی |
| --- | --- | --- | --- |
| مدیر | admin | admin | 123456 |
| کارشناس مسئول | masoul | 1234 | 123456 |
| نقشه‌بردار | tamizi | 1234 | 123456 |
| نقشه‌بردار | nikzad | 1234 | 123456 |

کد ورود بالا آزمایشی و محلی است. سرویس پیامک یا TOTP واقعی پیاده‌سازی نشده است.

در راه‌اندازی اولیه، درخواست‌ها از `data/cartable_all.json` وارد می‌شوند و ابتدا بدون کارشناس‌اند؛ کارشناس مسئول باید درخواست را ارجاع دهد.

## ارتقای نصب قبلی و حفظ اطلاعات

فایل‌های این نسخه را در همان پوشه قبلی `kroky-app-v3` جایگزین کنید. نام پروژه Compose، فایل `.env` فعلی و تنظیم Volumeهای قبلی را حفظ کنید تا همان دیتابیس و آپلودها متصل بمانند.

```bash
docker compose stop
# فایل‌های نسخه جدید را در همین پوشه جایگزین کنید.
docker compose up -d --build
docker compose logs --tail=80 backend
```

از `down -v` استفاده نکنید؛ این گزینه Volumeهای داده را حذف می‌کند. به‌روزرسانی نیازی به حذف دیتابیس ندارد. جدول‌های نسخه جدید به‌صورت افزایشی ساخته می‌شوند و Seed روی دیتابیس دارای کاربر دوباره اجرا نمی‌شود.

ثبت‌های قدیمی حذف نمی‌شوند. ثبت‌های فاقد فرم ساختاریافته در API جدید فهرست نمی‌شوند؛ برای انتقال آن‌ها باید کارشناس مسئول ثبت قدیمی را عودت دهد و نقشه‌بردار فرم جدید را تکمیل و دوباره ارسال کند. فایل DXF و عکس‌های قبلی قابل حفظ‌اند.

اگر در نصب قبلی مسیر آپلود را به `./uploads:/app/uploads` تغییر داده‌اید، همان اتصال را در Compose نگه دارید. فایل Compose این بسته به‌صورت پیش‌فرض Named Volume دارد.

## محل اطلاعات و پیوست‌ها

| داده | محل ذخیره |
| --- | --- |
| درخواست‌ها، کاربران و وضعیت گردش‌کار | جدول‌های قبلی دیتابیس |
| مشخصات فرم، تنظیمات برداشت و بازدید | `kroky_forms`؛ ستون‌های JSONB ساختاریافته |
| ردیف‌های حدود | `kroky_boundaries` |
| ردیف‌های بهره‌برداری | `kroky_land_uses` |
| شناسه DXF و عکس‌ها | `kroky_submissions` و `kroky_photos` |
| عنوان، توضیح، حجم و SHA-256 فایل‌ها | `kroky_file_metadata` |
| خود فایل‌ها | `/app/uploads/<request_id>/` در Volume آپلود |

مسیرهای فایل در دیتابیس نسبی‌اند. سرویس انتقال باید فایل را از `download_url` API بگیرد. فایل‌های اولیه پوشه `data` فقط منبع ورود داده اولیه‌اند و با ثبت کاربر بازنویسی نمی‌شوند. فایل فیزیکی JSON خودکار ساخته نمی‌شود؛ پاسخ API، JSON زنده از دیتابیس است.

جایگزینی یا حذف عکس از فرم، ارتباط آن با ثبت فعلی را اصلاح می‌کند. فایل‌های قدیمی روی دیسک برای بازیابی باقی می‌مانند و از خروجی ثبت جدید حذف می‌شوند. خطای حین ثبت باعث Rollback دیتابیس و حذف فایل‌های تازه همان تلاش می‌شود.

## API سرویس شما

راهنمای کامل همراه نام فیلدها در `API_GUIDE.md` قرار دارد.

```text
GET /api/integration/kroky
GET /api/integration/kroky/{request_id}
GET /api/integration/kroky/{request_id}/files/dxf
GET /api/integration/kroky/{request_id}/files/photos/{photo_id}
GET /api/integration/cartable
GET /api/openapi.json
```

فهرست پیش‌فرض فقط ثبت‌های تأییدشده را برمی‌گرداند. برای سرویس می‌توانید در `.env` مقدار `INTEGRATION_API_KEY` تعیین کنید و آن را در هدر `X-Integration-Key` بفرستید. در صورت خالی‌بودن این تنظیم، JWT مدیر یا کارشناس مسئول لازم است.

## بررسی‌های انجام‌شده

ساخت Vite، ۱۴ آزمون HTTP/ORM، آزمون React DOM و آزمون واقعی مرورگر بررسی شده‌اند. در آزمون مرورگر، پنل در عرض‌های ۱۳۶۶ و ۱۹۲۰ پیکسل، ردیف شش‌قسمتی کد ممیزی، هفت گزینه روش برداشت، پیش‌نمایش، بازگشت برای ویرایش، ثبت، بررسی کارشناس، تأیید و دریافت از API کنترل شدند. آزمون‌های دیتابیس با SQLite موقت و جایگزینی نوع ذخیره JSONB/Geometry فقط در کد آزمون اجرا می‌شوند؛ این جایگزینی در اپ تحویلی فعال نیست. تعریف جدول‌ها برای dialect PostgreSQL نیز کامپایل می‌شود. اجرای واقعی کانتینرها و PostGIS در محیط ساخت ممکن نبوده است.

اجرای آزمون‌ها:

```bash
python -m pip install -r backend/requirements-test.txt
python -m pytest tests -q
npm ci
npm run build
# آزمون اختیاری تعامل React در DOM؛ آزمون تصویری مرورگر نیست:
npm install --no-save jsdom
node tests/dom_smoke.cjs
# آزمون اختیاری مرورگر با دیتابیس موقت؛ سرورها را خودش اجرا و متوقف می‌کند:
npm install --no-save playwright
npx playwright install chromium
node tests/browser_smoke.cjs
```

برای اجرای آزمون‌ها با PostGIS، متغیر `KROKY_TEST_DATABASE_URL` را به یک دیتابیس آزمایشی خالی و قابل حذف بدهید. تست در صورت وجود جدول در آن دیتابیس متوقف می‌شود. هر بار اجرا باید روی دیتابیس آزمایشی مستقل انجام شود.

توسعه بدون Docker: بک‌اند به PostgreSQL/PostGIS نیاز دارد؛ `DATABASE_URL`، `SEED_DATA_DIR` و `UPLOAD_DIR` را تنظیم و از پوشه `backend` دستور `python -m uvicorn app.main:app --reload` را اجرا کنید. سپس `npm run dev` را در ریشه پروژه اجرا کنید. Vite درخواست‌های `/api` و `/uploads` را به پورت ۸۰۰۰ می‌فرستد.
